## 菜单：分类 + AI 设置（scripts/ui/pet_menu.gd）

原来菜单写死在 `pet.tscn` 里（19 条平铺，`item_N` 和 id 一一对应），条目一多就既没法分组、
也加不了子菜单。现在整棵菜单由 `scripts/ui/pet_menu.gd` 在运行时搭起来，**一级就是分类**：

```
互动          摸摸头 / 喂点东西 / 睡觉起床 / 跳一下 / 说点什么
位置与窗口     记住当前位置 / 回到右下角 / 只在小范围走动☑ / 窗口置顶 / 小·中·大
聊天与 AI      打开聊天框 / 让她想个话题 / 偷看屏幕看看 / 看一眼摄像头 /
			   主动说话☑ / 主动说话的频率 ▸（很少 / 普通 / 频繁 / 很频繁） /
			   定时偷看屏幕☑ / 定时看摄像头☑ /
			   让她用 dsh 干活☑ / 给她派个活… /
			   AI 服务设置… / 重新连接 AI 服务
开机与系统     开机自启动☑ / 隐藏任务栏图标☑ / 全屏时保持安静☑ / 托盘图标☑ /
			   自启动：已开启（显示用的一行）
工作台…        （派活 / 看原文 / 重启她 —— 见下文「工作台」）
设置…          （见下一节）
退出
```

分工是刻意的：`pet_menu.gd` 只管**菜单长什么样**（分组 / 条目 / 勾选状态 / AI 设置面板），
点了之后**干什么**仍由主脚本的 `_on_menu_id(id)` 决定（通过 `action` 信号转过去）。
所以加一个功能 = 菜单里加一行 + 主脚本 match 里加一个分支。

`pet.tscn` 里现在只留一个**空的** PopupMenu 节点（旧那 19 条 item 已删掉 ——
留着只会让人以为菜单还在场景里配）。

**顺手修掉的老问题**：菜单项以前**没有中文字体**（`.tscn` 里只有中文文本、没配字体，
而项目默认字体渲染汉字会掉字）。现在菜单挂上系统里的雅黑 —— 注意
**`PopupMenu` 不是 `Control`**（它是 `Popup → Window`），`add_theme_font_override`
在它身上不存在，得走 Theme：

```gdscript
var th := Theme.new()
th.set_font("font", "PopupMenu", font)
menu.theme = th
```

> 写这段时踩了一次：参数类型写成 `PopupMenu`，再拿 `Button / Label / LineEdit` 去调，
> 直接**整脚本编译失败**（`Invalid argument for _apply_font(): argument 1 should be …`）。
> 面板上的控件走 `Control`，菜单走 Theme，两条路不能混。

### 「退出」点不动（已修）

症状：右键菜单里点「退出」**毫无反应**，其它条目都正常。

原因不在退出那一步，而在**根菜单从来没连过 `id_pressed`**：子菜单是在 `_submenu()` 里
各自连的，而根菜单上的条目（「退出」，后来还有「设置…」）走的是根菜单自己那条信号，
谁都没接。于是点击被 Godot 正常发出、正常高亮、然后**掉在地上**。

```gdscript
# 子菜单各自连，根菜单也得连 —— 漏了这一句，菜单看起来一切正常，只是点了没反应
if not _menu.id_pressed.is_connected(_on_item):
	_menu.id_pressed.connect(_on_item)
```

这类 bug 读代码很难发现（信号、条目、id 全都对），所以固化成了探针：
`tools/probe_settings.gd` 第 1 段就断言"根菜单的 `id_pressed` 至少接了一个回调"。

退出还顺手做干净了三件事（`_quit()`）：收起面板（输入框正抢着键盘焦点时看着像没反应）、
主动收掉托盘辅助进程（不等它自己发现我们没了，图标立刻消失）、存一次设置。


## 设置面板（scripts/ui/pet_settings.gd + pet_ui.gd）

### 表驱动：加一项设置只动三处

面板长什么样、值怎么钳制，全部来自 `pet_settings.gd` 里那张 `SECTIONS` 表
（`k` 键名 / `t` 控件类型 / `label` / `hint` 鼠标提示 / `min·max·step` / `options·vals`）。
主脚本那边只多一张 `SETTING_VARS`（键 → 检查器变量名）。所以加一项设置要动的地方是：

1. `pet_settings.gd` 的 `SECTIONS` —— 长什么样、范围多少；
2. `desktop_pet.gd` 的 `SETTING_VARS` —— 存到哪个变量（按钮和系统那几个例外，见 `_apply_settings`）；
3. `SETTING_SAVED` —— 要不要落盘（漏了就是"能改能保存，重启又变回去"，界面上完全看不出来）。

第 3 条是最容易漏的，所以有个交叉检查：`tools/probe_memory.gd` 的离线段会遍历表里每个键，
断言"主脚本认它 **且** 它会落盘"。

### 几个刻意的设计

- **提示一律做成鼠标悬停**（tooltip），不占一行版面：25 项每项都带一行灰字说明的话，
  滚一屏都看不完
- **危险动作不做弹窗确认**：项目里 `embed_subwindows=false`，弹窗会变成**另一个 OS 窗口**，
  而桌宠平时是 `no_focus` 的，那种窗口很难收场。改成"同一个按钮点两下"（5 秒内）
- **面板占满整窗**，不是居中固定尺寸：窗口本身只有 330×470，缩放档还会把它变小，
  固定尺寸在小档下会溢出到窗外
- **输入框的字色必须自己指定**：我们把底色换成了白的，但默认主题的字色是给深色底准备的
  浅灰 —— 结果是"打进去的字几乎看不见，只有光标在动"。勾选框同理
  （这个毛病原来的 AI 设置面板里就有，只是没人细看）

### 值存在哪、什么时候生效

- **检查器变量**（`@export`）是出厂值，也是运行时的唯一出处；
  `user://pet_chat.cfg` 记你改过的那些（`chat` 段是老的四个开关，`app` 段是面板新加的）
- 打开面板时主脚本把**运行时真实值**灌进去（自启动去注册表读、隐藏任务栏读 shell），
  不是读存档 —— 两边不一致时以真实状态为准
- 点保存后：落到变量 → 落盘 → **立刻生效**（重数那几个倒计时、重拼人设、按新设置调 shell）

> **这里踩过一个真坑**：`_apply_settings()` 多了一个 `push_system` 参数，启动时传 `false`。
> 原因是启动时读回来的只是"上次的偏好"，而自启动的真实状态在注册表里，可能在
> 任务管理器里被关掉过 —— 每次启动都按我们记的值写一遍注册表，等于把别处的改动盖掉。
> 具体后果是：`autostart_enabled` 这个导出变量默认 `false`，存档里是 `true`，
> 于是流程变成"启动 → 比对不一致 → `set_autostart(false)`"，**一开机就把用户开着的自启动关了**，
> 而且完全看不出来是谁关的。只有用户在面板里点保存才该写注册表。

### 面板零件复用（scripts/ui/pet_ui.gd）

AI 设置面板和设置面板本来各写了一份 `_label()` / `_edit()` / 卡片样式，改一处忘一处，
两个面板的风格就开始漂。现在零件都在 `pet_ui.gd` 里（全是 `static`，不持有状态），
两个面板共用一套长相。

> 验证：`tools/probe_settings.gd`（要真窗口，不能 `--headless`）—— 四段：根菜单信号有没有接上 /

## 工作台：让她给自己升级（scripts/ui/pet_workbench.gd）

右键 →「工作台…」（一级菜单里）。这个面板是**给"正儿八经的活"**用的，
尤其是**让她改自己的代码**：

```
工作台 / 档位 high｜权限 read-only
在哪儿干    [<项目目录>] [项目目录]
			☑ 自我升级（附上项目说明，并允许改文件）    ← 勾了就把工作目录指到项目、并允许改文件
			☐ 允许她改文件
要她做什么  [给小蓝加一个"今天几号"的菜单项            ]
			[派活] [清空]                     推理档按任务自动挑
结果        [（dsh 的原文都在这儿，不经过她的转述）    ]
			[打开工作目录] [重启她（应用改动）] [关闭]
```

| | 聊天框里的「干活：…」 | 工作台 |
| --- | --- | --- |
| 适合 | 顺手的小活（查一下、算一下） | 正儿八经的活、**改自己的代码** |
| 结果 | 她**用自己的口气转述**一两句（人设不破） | **原文摆在这儿**（她要转述就丢了细节） |
| 任务长度 | 一行 | 好几行 |
| 工作目录 / 权限 | 继承默认（只读） | 能选，还能"允许改文件" |
| 干完 | 她说完就完 | 能一键**重启她**加载新代码 |

### 自我升级这一圈是怎么转的

1. 勾「自我升级」→ 工作目录指到项目目录、自动勾上"允许改文件"、任务前面加一段项目说明
   （她是通读代码的人，那段只说"这是哪儿、从哪看起、改完要跑什么验证"）
2. 派活 → dsh 在**你指定的工作目录里**读代码、改代码
3. 结果原文留在这儿；想看她动了什么就点「打开工作目录」
4. 点「重启她（应用改动）」→ GDScript 是启动时加载的，不重启不生效

权限那一步在 dsh 那边只放宽到 **`workspace-write`** —— 也就是**只能改工作目录里的东西**，
改不到别处去。`danger-full-access`（不限制范围）**故意不提供**：自我升级用不着，
那等于把整台机器交出去。

两个刻意的细节：

- **不勾"允许改文件"时不会去动你原来的权限设置** —— 只看代码、回答问题用不着改它。
  这一项的做法是"需要放宽时才临时放宽"，绝不主动写回 `read-only`（你本来配的可能是别的档）
- 跑完**原样写回**（和推理档同一套，见上文那个纯字符串函数）：`k` 个键都在同一个
  `settings.yaml` 里，一次改完一次写回 ✓

工作目录这么猜（猜错不致命，面板里能改，改完记住）：`res://` 下有 `project.godot` 就用它
（编辑器里跑、从源码跑）；否则看 **exe 旁边**哪个子目录里有 `project.godot`
（导出版用 junction 指回源码的情况，实测 `dist/pet.exe` 旁边就是 `pet/`）；
都没有就用 exe 所在目录。

「重启她」的顺序是**先拉起新进程、再退自己** —— 反过来的话会有一小段"旧的没了、新的还没起来"。
怎么拉起自己沿用开机自启动那套规则（导出版 = exe 自己；编辑器里 = Godot + `--path`），
所以不管她从哪跑起来的，重启后还是原来那个形态。

> 实测（真给它写权限、工作目录指到项目里）：让它新建一个文件，6.9 秒做完，文件真写出来了，
> 内容也对；跑完 `settings.yaml` **原样还原**（`high` / `read-only` 一位没变）。

> 版面这个坑值得记一句：状态那行字一开始和"标题 + 弹簧"挤在同一行，
> 而它带自动换行 —— 结果被压到只剩几像素宽，**竖着排成一条**，高度撑到一百多像素，
> 把下面所有东西顶出窗口。截图才发现（`hint()` 那种带 autowrap 的标签别和弹簧同行）。
