# 聊天与 AI

> 这个目录装的是她的"嘴"：对话客户端、流式解析、连接与重试、主动开口、快速回答，
> 以及离线时的降级。

## 两个后端随便切

菜单「聊天与 AI」→「AI 服务设置…」里选一下来源就自动填好地址和模型（选完还能手改）。
两个都是 **OpenAI 兼容协议**，桌宠只换地址 / 密钥 / 模型名：

| 来源 | 地址 | 文本模型 | 视觉模型 | 要钱吗 |
| --- | --- | --- | --- | --- |
| **官方 API** | `https://api.deepseek.com` | `deepseek-flash` | `deepseek-v4-flash-vision-exp` | 要（付费 key） |
| 本地网页版代理 | `http://127.0.0.1:8520/v1` | `deepseek-chat` | 无（看不到图） | 不要，但要网页端 userToken 不过期 |

| 项 | 说明 |
| --- | --- |
| 鉴权 | `Authorization: Bearer <key>`（官方填 `sk-` 开头的付费 key；本地填管理页第 ② 栏那串） |
| 协议 | `POST {base}/chat/completions`，SSE 分片走 `choices[0].delta.content`，收尾 `data: [DONE]` |
| 探活 | `GET {base}/models` —— **故意不用 `/healthz`**：那是本地代理专有的，官方 API 上会 404，会被误判成"服务没起来"然后永远退回本地台词 |
| 密钥存哪 | 存进 `user://pet_secret.dat`（加密），配置文件里那两项恒为空 |

服务在跑就是真回话，**服务没起就退回本地台词**，不会报错、也不会把窗口卡住。

> 官方 API 回文本会**带 `reasoning_content`**，而流式分片里它经常是 **`null`** ——
> GDScript 的 `String(null)` 会直接抛 `Nonexistent 'String' constructor` 把整条流打崩，
> 所以取值必须先判类型（`_as_text()`）。

### 偷看屏幕 / 看摄像头：走**视觉那条独立链路**

这两个功能都要"看图说话"，所以**不走文本那个客户端**，而是走另一条：`vision_url` +
`vision_model` + 同一个 key（`vision_access_key` 留空就复用文本的）。独立客户端 = 独立连接，
所以她正在说话时照样能截屏去问，两张图也不会互相排队。

| 功能 | 图从哪来 |
| --- | --- |
| **偷看屏幕** | `DisplayServer.screen_get_image()` → 缩到 1280 宽 → JPEG → data URL |
| **看摄像头** | **Godot 自带的 CameraServer** 采集，不依赖外部程序 |

**主动说话也会"先瞥一眼"**（默认开）：她自己找话题时按 `proactive_peek_chance`（默认 0.35）
的**概率**先抓一张屏幕，拿着画面（以及"主人前台开着什么窗口"）说话 —— 不然她只能凭**记忆**
起话头，而记忆是过去的事，主动开口就容易"和主人正在干的事不一样"。

抓到的图**只在那一轮**发给模型 —— 它**不进对话历史**，也没有任何"上次那张图"的缓存。所以她
之后还提那件事，是因为那次偷看**写进了一条文字记忆**，而不是图片被反复喂回去。

**抓不到的情况**：抓屏走的是**桌面合成**这一层，所以有两类画面它看不到：

1. **独占全屏**的游戏 —— 它不进桌面合成，抓到的只有桌面；
2. **带反作弊**的游戏 —— 反作弊会**主动屏蔽截屏**，这是它的设计目标，不是 bug。

这时她只会拿到一张桌面，所以提示词里明确要求她"**只说你真看到的，别猜主人在玩什么**"。
想让她真看到：把游戏改成**无边框窗口**（独占全屏那条能解决；反作弊那条改不掉）。

**摄像头的两个坑**：

1. **必须先 `CameraServer.set_monitoring_feeds(true)`** —— 不调的话 `get_feed_count()` 恒为 0
   并报 `not actively monitoring feeds`
2. 摄像头刚打开时纹理要晚几帧才有内容，所以要等（最多约 5 秒），拿不到就认输
3. `_camera_look()` 是**协程**（要 await 等帧），所以 `_check_camera()` 里**故意不 await** ——
   那条链跑在 `_process` 上，在那儿 await 会让本帧提前返回、状态机被重入

> 本地网页版那条链路看不到图（它只把 messages 拼成文本），所以「来源」选本地版时视觉模型
> 留空即可，这两个功能会自动提示"还没配好看图的模型"。

### 令牌过期是这个链路最常见的故障

网页端 userToken 会随登录态过期（通常几天到几周）。过期后上游返回 `40003`，而代理会把这段错误
**当成正文**吐出来。桌宠这边特意识别它：整段以 `[代理错误]` 开头（**前面常带几个换行**，所以
判断前要先去掉空白 —— 不带 strip 就匹配不上，报错会被当回复念出来），识别到就换成一句
"去管理页重新粘贴 userToken"。

修法是纯操作：打开 <http://127.0.0.1:8520/admin> 重新粘贴，代码侧不用动。

### 怎么开始聊

| 操作 | 效果 |
| --- | --- |
| **双击角色** | 弹出底部输入框，打完字回车发出去 |
| 右键 →「聊天与 AI」→「让她想个话题」 | 不等你开口，她自己找个话题说一句 |
| 右键 →「聊天与 AI」→「偷看屏幕看看」 | 截当前屏幕发给她 |
| 右键 →「聊天与 AI」→「看一眼摄像头」 | 拍一张并评论（另一条链路，见下） |
| 右键 →「聊天与 AI」→「主动说话」☑ | 定时主动搭话的总开关 |
| 右键 →「聊天与 AI」→「定时偷看屏幕」☑ | 定时截屏那条链路的开关（默认关） |
| 右键 →「聊天与 AI」→「定时看摄像头」☑ | 摄像头那条链路的开关 |
| 右键 →「聊天与 AI」→「AI 服务设置…」 | **改后端地址 / 密钥 / 模型**，存盘并立刻重连 |
| 右键 →「聊天与 AI」→「重新连接 AI 服务」 | 服务刚起来、或改完设置想立刻重试时用 |
| **Esc** / 点面板外面 | 关掉输入框或设置面板 |

三个勾选项点一下立刻翻转，气泡里回一句「xxx：开 / 关」，并写进 `user://pet_chat.cfg`。

回复是**流式**的：服务端的 token 一个个到，气泡就一个字一个字往外冒，说完再淡出。输入框上方
常驻最近几行聊天记录（`chat_log_lines`）。

### 参数（检查器分组「聊天」）

| 参数 | 默认 | 作用 |
| --- | --- | --- |
| `chat_enabled` | true | 总开关。关掉 = 完全不联网，回到纯本地桌宠 |
| `chat_url` | `http://127.0.0.1:8520/v1` | AI 服务地址 |
| `chat_access_key` | `sk-ds-...` | 访问密钥（填进加密文件，不落在配置文件里） |
| `chat_model` | `deepseek-chat` | 模型名 |
| `chat_system_prompt` | **空** | 额外要求。她的**人设本身**在 `pet_persona.gd` 里；这里填的会作为"主人的额外要求"追加到人设后面 |
| `chat_persona_name` | `小蓝` | 她的名字（写进人设，菜单里可随手改） |
| `hibernate_when_offline` | true | 联系不上 AI 服务时她进**假死**（见文末） |
| `memory_enabled` | true | 长期记忆总开关。关掉 = 她每次都像第一次见你 |
| `memory_ai_extract` | true | 让她用模型抽记忆。会多一次非流式请求；关掉只影响自动抽取，本地规则的记忆照常 |
| `memory_ai_every_sec` | 30 | 两次 AI 抽取之间的最小间隔 |
| `memory_summary_every` | 6 | 每几轮更新一次"工作记忆" |
| `memory_observe` | true | 把"主动搭话 / 偷看屏幕"说的内容也选择性记进长期记忆 |
| `chat_log_lines` | 3 | 输入框上方显示几行聊天记录 |
| `proactive_enabled` | true | **开局默认值**，之后由菜单「主动说话」切换并存盘 |
| `self_talk_enabled` | true | 太久没人理她就自己找话说 |
| `self_talk_after` | (300, 900) | 安静多少秒之后主动开口（随机区间）。**"普通"档的基准** —— 其余三档按它缩放 |
| `peek_enabled` | **false** | 定时偷看的开局默认值 |
| `peek_every_min` | 5.0 | 偷看的间隔（分钟） |
| `camera_look_enabled` | **false** | 定时看摄像头的开局默认值 |

> **地址 / 密钥 / 模型这三项会写进存档**，因为它们现在可以在菜单里改 —— 改完立刻重连，不用
> 重启。存档里**缺键**时落回检查器里的值 —— 老存档不会把新加的开关静默关掉。

### 两种"她主动开口"的来源

服务端没有推送通道，所以只有两条：

1. **桌宠自己计时**：`self_talk_after` 时间到、且没人在跟她互动，就发一句提示词让模型找话题。
   菜单里「让她想个话题」是同一路，只是手动触发 —— **手动那条不受开关限制**
2. **偷看屏幕后评论**：定时截屏那条链路

> 两条都受菜单「主动说话」管。

## 摄像头：Windows 上做不到（结论，别再往这个方向查）

**不是相机的问题，也不是权限问题** —— **官方 Godot 的 Windows 构建里没有摄像头后端**，
`CameraServer` 只是个空壳 API。

判据：在引擎二进制里找符号，`CameraServer` / `CameraFeed` 都在，但 Windows 上抓摄像头的唯一
途径 Media Foundation 那组符号（`MFStartup` / `MFEnumDeviceSources` / …）**一个都没有**。
表现完全吻合：`get_feed_count()` 恒为 0、`set_monitoring_feeds(true)` 不报错、`--verbose` 下
一个字都不提摄像头。

系统侧一切正常（设备管理器有、WinRT 枚举到 1 个、权限开着、自带相机应用能出流），
**是引擎这一侧枚举不到**。

要做得换一条采集路径（比如外部程序），但代价是引入一个后台进程 —— 权衡下来不值得，所以没做。

现在的行为是"优雅退化"：菜单点「看一眼摄像头」，她会说
**"唔…我这台机器上用不了摄像头诶。"** —— 不会再让人以为是相机或权限坏了。

> 采集代码在 `_camera_shot()`：它把失败原因分开 —— "没找到设备"（枚举 0 个）、
> "设备在但取不到画面"（被占用 / 硬开关）、"压 JPEG 失败"。前两种的排查方向完全不同，
> debug 构建的日志里能看到具体是哪一种。

如果她在别处说"我这边没找到摄像头诶…"，那是 `get_feed_count()` 为 0。按这个顺序查：
设备管理器里在不在 → 系统认不认它是采集设备 → **"允许桌面应用访问相机"**有没有开（最容易漏
这条）→ 有没有被别的程序占用 → 换个 Godot 版本或换台机器跑 `tools/probe_camera.gd`
（**要带窗口跑**，`--headless` 下枚举恒为 0）。

## 为什么聊天那条不用 HTTPRequest

`HTTPRequest` 只在请求**结束**时用 `request_completed` 一次性给出整个 body，
`get_downloaded_bytes()` 只给进度数字、拿不到内容 —— SSE 就没法边收边显示。所以
`pet_chat.gd` 用 `HTTPClient` 自己推一个状态机，每帧由主脚本的 `_process` 调 `tick()` 推进，
**全程同步、不 await、不起线程**：既不阻塞渲染，也不和窗口操作打架（`_process` 里 await 会让
本帧提前返回、状态机被重入）。

里面是两条独立通道：`_sse` 跑长流式对话（一次可能 5~30 秒），`_short` 跑探活和短请求 ——
长流占着连接时短请求才不会排队干等。

### 三个坑

**1. keep-alive 读完 body 后，status 会从 `STATUS_BODY` 退回 `STATUS_CONNECTED`。**
把它当成"刚连上"的话会**反复重发同一个请求**。现在这个分支会看 `phase`：`CONNECTING` 才发
请求，已经有响应码了就判定"这一轮收完了"。

**2. 按行切 SSE 必须按字节切。** 直接对可能以半个多字节字符结尾的 chunk 调
`get_string_from_utf8()`，截断处会被换成 `U+FFFD` 而且那几个字节**永久丢失**、拼不回来。
所以 `_drain_sse()` 是在 `PackedByteArray` 上 `find(0x0A)` 切行，只对切出来的完整行解码。

**3. `image_url.url` 得是完整的 data URL，不能只放 base64 裸串。** 上游要的是"一个 URL"，
要么 http(s)，要么完整的 `data:image/jpeg;base64,…`；只放裸串会回
`400 Unsupported image_url format`。

### 输入框怎么拿到键盘

桌宠窗口是 `NO_FOCUS` 的，不然会抢走别的窗口焦点。双击她时先
`window_set_flag(WINDOW_FLAG_NO_FOCUS, false)` + `window_move_to_foreground()`，关掉输入框
再设回 `true`。

输入框和气泡都用 `SystemFont`（`Microsoft YaHei UI` / `Microsoft YaHei` / `SimHei`），
不指定的话 CJK 字形是空的、中文根本显示不出来。

### 流式冒字为什么不能走 `_say()`

`_say()` 自带 1.8 秒的淡出 tween。流式显示时是**直接改 `_bubble.text`**，一个字都不经过
`_say()`；等整段回复收完才用 `_say(完整回复)` 收尾。否则那句淡出会在冒字途中把气泡藏掉。

### 几条链路共用一个气泡

聊天流、偷看屏幕、摄像头都会往**同一个气泡**里写字，所以两两之间必须有闸：

- `_camera_busy` 和 `_chat_streaming` 是**两个独立的标记**，绝不互相清。早先
  `_on_camera_look_done()` 顺手把 `_chat_streaming` 也清了 —— 收流和摄像头一重叠就会变成
  "字还在冒、状态却说没在冒"，收尾判断全乱套
- 摄像头那条起手式走 `_hold_bubble()`（掐 tween + 显示气泡，**不碰任何忙标记**），
  不是 `_begin_stream_bubble()`（那个会把 `_chat_streaming` 置真）
- 同时点另一条只会得到一句「等我先把这句说完～」，不会把正在冒的字顶掉

## 离线假死：联系不上时她只做基础动作

判据只有一个：聊天总开关关着，**或者**后端探活失败。开局那一两秒探活还没回来，她也先按离线算
—— 保守方向是对的，宁可安静，别往死服务上撞。

进了假死，**停掉的全是会自己发起的事**：

| 停 | 为什么 |
| --- | --- |
| 主动说话 / 生闷气 | 本来也会退本地台词，但那样她等于一直在"假装聊天" |
| 定时偷看屏幕 / 看摄像头 | 截了图也没地方发，连截图这步都省 |
| 记忆抽取 / 工作记忆摘要 | 那些请求注定失败，白花时间 |
| 聊天发消息 | 挡下来并说清楚"联系不上"，**输入框里的话不动**，连上了你重试就行 |
| 聊天那条派活 | 同上。**工作台那条不受限** —— 那是你明确的指令，dsh 有自己的账号 |
| 自己乱走 | 待在原地（这道门在骰子**前面**，`move_chance` 调到 1.0 也压不住它） |

保留的基础功能：摸头 / 喂食 / 睡觉 / 拖拽 / 菜单 / 本地台词 / 眨眼呼吸 —— 被摸了照样有反应，
只是不再主动做事。

怎么知道她进了假死：菜单「聊天与 AI」最底下那行状态；断网那一刻她说一句（**只说一次**，不每轮
探活失败都念叨），恢复时再说一句"好了"。

开关是 `hibernate_when_offline`（默认开）。关掉 = 断网时她照旧装作没事。

> 验证：`tools/probe_offline.gd` —— 直接拿 `PetChat.reachable_set()` 把探活结果扳成离线，
> 逐项断言"该停的停了、该留的留着、恢复后又能走"。
