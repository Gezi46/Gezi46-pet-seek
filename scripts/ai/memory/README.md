# 人格与长期记忆

> 她是谁、记得什么、怎么忘。系统提示词就是在这里按话题拼出来的。
>
> 返回 [项目主 README](../../../README.md)

## 她是谁：一行字是不够的

整份人设写在 `scripts/ai/pet_persona.gd` 里，分十段，而且**拼装顺序是有意的**："她是谁"在最前
面、参考资料在最后。放反了，模型会把参考资料当成任务书，语气立刻变成答题机器人。

| 段 | 写的是什么 | 为什么要有 |
| --- | --- | --- |
| 身份 | 18 岁、女生、今年 6 月刚高中毕业、暑假在家、住在电脑里 | 定死年龄和处境 |
| 不是 AI | 不许自称 AI/助手，不许说"我可以帮你" | 客服腔是最大的破功点 |
| 性格 | 小傲娇、迷糊、爱吐槽、明确的喜恶 | 给情绪反应一个有依据的来源 |
| 怎么说话 | 1~2 句、口语、不写 markdown、先接情绪再给方案 | 决定"像不像在发微信" |
| **认知水平** | 高中学的还记得；没上过大学、没工作过；**不会就说不会，禁止编造** | 最像真人的一块，也最容易被忽略 |
| 小习惯 | 顺口提自己刚在做的事；被问"你有身体吗"怎么带过去 | 让回复有"她刚才在干嘛"的连续性 |
| 关于主人 | 长期记忆 | |
| 现在 | 日期时间 + 她刚在做什么 | 所以她会知道"都十点多了" |
| 常识参考 | 按这句话的话题挑几条 | 见下 |

**认知边界那条是重点**：光说"你是 18 岁"没用，得写清楚*哪些会、哪些必须说不会*。写清了之后，
问"什么是傅里叶变换"她会说没学过、大学的东西；问"3x+5=20"她会算；问年龄她会答十八。

### 常识：按话题挑，不整库塞

`scripts/ai/pet_common_sense.gd` 是一份"这个年纪该知道的事"（校园升学、学科基础、生活常识、
情绪人际、网络流行、社会常识、自然世界，约 60 条），外加按日期注入的时令条目。

不整库塞进 prompt 有两个原因：token 白烧；**更要紧的是会稀释人设** —— 参考资料越长，"她是谁"
那几句的比重越低。所以按用户这句话里的关键词挑 5 条左右。

农历节日只写"有这么个节"、**不写具体日期** —— 日子每年都不一样，写死她就会报错日子，那比
不知道更糟。

### 长期记忆：把 giftia 那套机制移植过来

原来"记忆" = 内存里的 20 条对话历史：重启就没，聊长了也会被截断。现在是把
`memory_manager.py` 的**机制**移植成 GDScript：

| 机制 | 做法 |
| --- | --- |
| 遗忘曲线 | `R = e^(-t / (S*24+1))`，`S = 0.3 + 重要性*0.5 + min(复习次数*0.15, 1)` —— 被反复提起的记得牢 |
| 记忆分层 | 核心/重要/常规（按重要性 + 情感强度自动分配），遗忘强度 10/2/1，检索权重 1.0/0.8/0.5 |
| 重要性打分 | 情感强度 0.4 + 信息密度 0.3 + 被想起次数 0.2 + 长度 0.1 |
| 情感分析 | 12 类情绪的关键词表 + **语境翻转**（"我努力了还是失败了"不能判成开心）+ 程度副词/否定词 |
| 检索 | 两路召回（字面 n-gram 匹配 + 标签匹配）→ RRF 融合 → 按 检索质量.50 / 时间.20 / 情感.15 / 重要性.10 / 层级.05 重排 |
| 工作记忆 | 跨对话的整体摘要 + 还没聊完的话题 + 主人最近的情绪 |
| 档案卡 | 字段级事实（名字/年龄/职业/地点/生日/喜好/雷点/宠物/备注），**不受遗忘曲线影响** |

移植时降级的两处（环境里真没有，不是偷懒）：

- **语义向量 → 中文 n-gram 子串匹配**：giftia 用智谱 embedding，而桌宠直连 DeepSeek，它没有
  embeddings 接口。好在 giftia 的 `_match_score` 本来就写了"向量不可用时降级到字符匹配"。
  代价是**换个说法就可能找不着**（"我平时爱喝什么" vs 记忆里的"主人喜欢冰美式"），所以补了
  一张 `TOPIC_HINTS` 话题扩展表。
- **SQLite / LangChain / mem0 → JSON 文件 + 桌宠自己的 chat 客户端**：不为记忆重新引入 Python
  后端。

### 提示词怎么排，才吃得到前缀缓存

服务商按"**逐字相同的最长前缀**"给缓存折扣，所以消息顺序是刻意设计的：

```
[system]    人设（她是谁 + 主人的额外要求）        ← 逐字不变，每次请求都一样
[user]      …历史…
[assistant] …
[system]    这一轮的上下文（关于主人 + 现在 + 常识）  ← 每轮都变
[user]      这一句
```

- 人设那半在 `PetPersona.build()`，**只放不会变的东西**；每轮会变的（记忆检索结果、日期时间、
  常识参考）在 `PetPersona.build_context()`，由 `PetChat` 的 `context_provider` 回调附到
  **历史之后**
- 这么排之前：记忆块夹在人设中间 → 缓存从那一句就断了，**连后面的历史都按原价算**
- 上下文**不写进 `_history`**（它是"此刻的参考"，不是对话内容）—— 写进去的话下一轮的前缀就
  不再是这一轮的延长线了

两条从实测数据里读出来的、反直觉的结论：

1. **命中按 64 token 一块跳**，不是按字算的
2. **服务商总会扣掉尾部约 160 token 不记命中**（把完全一样的请求原样发两遍，第二遍也命中不全，
   应该是写缓存有延迟）。所以"把人设字数凑到 64 的整数倍"**不值得为它改人设**；唯一白赚的
   方向是把**每轮都在变**的那段压小，而不是把稳定段堆长

**已经做的瘦身**（纯格式压缩，信息一条没少）：人设里的"现在"压成一行；常识参考的标题压短；
**记忆块有 320 字上限**，超了就从**末尾**整行丢（末尾是按这句话检索出来的，丢了只是这轮少提
一嘴；档案卡和工作记忆在前头，不丢），并且不留"只有标题、后面空掉"的段落。

**应用自己也能量**（不用起探针）：

- `pet_chat.last_usage` / `last_once_usage`：原样存着服务商给的 token 账
- `cache_hit_tokens()` / `cache_miss_tokens()`：字段名各家不同（DeepSeek 给
  `prompt_cache_hit_tokens`、OpenAI 只给 `prompt_tokens_details.cached_tokens`），统一从这里取
- **调试版**每轮会打一行 token 账 —— 正式版不打
- 流式那条路要拿到 usage，请求里得带 `"stream_options": {"include_usage": true}`。万一某个后端
  因此报 400，把那行删掉即可 —— 只影响"能不能看到账"

> 换个后端跑 `tools/probe_cache.gd`，如果**没有** `prompt_cache_*` 字段，说明那个后端不做前缀
> 缓存，那么"提示词怎么排"对省钱就没有影响。

### 换后端要过哪几道

key 只存在 `user://pet_chat.cfg` 里 —— **不进仓库**。导出版和编辑器用的是同一个 user 目录
（`%APPDATA%\Godot\app_userdata\桌宠`），所以配置只改一处。

换任何后端都按下表过一遍（"怎么应对"那列就是代码现在的行为）：

| 项 | 怎么应对 |
| --- | --- |
| 探活 `GET {base}/models` | 已经用它（原来打 `/healthz` 是本地 web-api 专有的） |
| `stream_options.include_usage` | 接受就保留；不接受会自动摘掉 |
| 看图格式 | 代码发 `data:image/jpeg;base64,…`，data-url 和纯 base64 都收 |
| **免费额度 429** | **自动重试**：等 2.5 秒把同一条请求**原样**重发，最多 2 次。重试在连接层做，聊天 / 记忆 / 候选都不知道这件事 |
| **带思考的模型吃光预算** | `max_tokens` 给小了正文就是空的。后台那条默认 **2000** |
| 错误塞在流里 | `_handle_event` 认识它，把 `message` 原文报出来 |
| 失败时的提示 | 带上 HTTP 状态码（401 = key 不对、404 = 地址不对、429 = 太挤） |

⚠️ **401（key 不对）不重试** —— 重试多少次都不会好，要立刻报出来而不是白等她几秒。

**"反应很慢"的根因是思考。** 好些 flash 模型**默认都带思考**，同一句"说一句十个字以内的话"
能拖到十几秒，而且预算被思考吃光时**正文是空的**。所以 `PetChat.no_think` **默认 true**，
请求里带 `"thinking": {"type": "disabled"}`（流式和一次性两条路都带）。桌宠要的是"像在发微信"
的一两句话，思考换不来质量，只换来十几秒的沉默。

不认这个参数的后端会回 **400** → `_note_unsupported()` 自动把它摘掉并记住，之后不再发
（**换模型不会因为这一项卡死**）。

### 实时时间 / 距上次说话

- `PetPersona.now_line()`：读系统时钟，精确到分钟（`2026年9月22日 周二 19:51，晚上`），时段用
  口语（说"晚上"不说"20 时"），凌晨会补一句"主人这么晚还没睡"的情境提示（**只写情境、不写成
  台词**，不然她每句都提这件事）
- **距上次说话多久**：宿主算好传进来（`gap_min`），3 分钟说"距上次说话 3 分钟"、300 分钟说
  "5 小时"。**不给就不提** —— 免得她编"我们好久没聊了"

### 记忆是怎么长起来的（两条路）

1. **本地规则**（零成本、立刻生效）：抽自述式的话（"我叫…""我不喜欢…""记住…"）写进档案卡
2. **模型抽取**（`memory_ai_extract` 开着时）：每轮对话后发一次非流式请求（`ask_once`，
   **单开一条连接，不打断正在流的对话**）。提示词照搬 giftia 那版的严格规则：只取"明确说出"
   的、禁止推测、禁止把 AI 的建议当成用户的事实。另外每 `memory_summary_every` 轮更新一次
   工作记忆

> 抽错的记忆会留在档案里、反复影响后面所有对话，所以**宁少勿滥**：规则抓不到的先不管，模型
> 那边用"只输出 JSON + 没东西就返回 `[]`"兜着。

## 主动说话 / 偷看屏幕说的内容，也会进记忆（但要"选择性"）

打字聊天是**整轮**记下来的（历史 + 工作记忆 + 抽事实）。主动搭话、偷看屏幕、看摄像头这三条
**不能**这么干 —— 它们每天会产生好几条，而且大多是"嗯嗯～""嘿嘿"这种，整轮存进去会把档案冲成
流水账，把真正重要的事挤掉。

所以它们走的是**四道筛子**（逐层收紧）：

| 筛子 | 挡掉什么 |
| --- | --- |
| 1. 长度 / 中文实字数 | "嗯嗯～""嘿嘿"这种没信息量的，**连模型调用都不用发** |
| 2. 文本去重 | 同一句说过就不再记一遍 |
| 3. 重要度 + 遗忘曲线 | 信息量低的自己淡掉、被清掉 —— "选择性"真正落地的地方 |
| 4. AI 二次筛选 | 让模型只挑"**关于主人**的事实"（她在做什么、在意什么），挑不出来返回 `[]`。撒娇、感慨、玩笑在这一层被挡掉 |

第 4 道用的是 `PetMemory.OBSERVE_PROMPT`（和从主人话里抽事实的 `FACT_PROMPT` 分开）—— 因为它
面对的是"她自己说的话"，要提炼的其实是**她在屏幕/摄像头里看到了什么**，比如她说"你在赶活儿
啊，赶时间 吧"，值得记的是"主人当时在赶一个活儿"。

记下来的形式带来源前缀，她以后才能顺着提：

```
她偷看屏幕时看到：主人在赶一个活儿，好像挺赶的
她主动聊到：……            （她自己找的话题）
她看摄像头时看到：……
```

后台那条抽取请求和聊天共用同一个节流 —— 不能因为她多看了几眼屏幕就多花钱。
整个开关是 `memory_observe`。

## 快速回答按钮 / 生闷气

**快速回答**：她说完话，**气泡下面会冒出几个按钮**，点一下就当你说过那句话（25 秒后自动收起）。
两个时机：她主动开口之后（概率 0.7）、以及**聊天之后**（概率 **0.20**）。

**为什么是概率而不是每次都给**：每次都给就成了一张"必看的表"；有时有、有时没有，才像随手递
过来的一句话。两个概率都能在设置面板里调。

**按钮上的字分两层**：

1. **本地那组立刻顶上** —— 要"立刻"能点，等模型一秒多就不叫快速回答了。顺序每次打乱，而且
   尽量不跟上次同一个开头（池子就那几句，原样重复一眼能看出是写死的）
2. **模型那组随后换上去**：拿她刚说的那句再问一次小模型，让它现编三句更像样的。洗不干净 /
   没回来 / 关掉开关，就继续用本地那组 —— **按钮不会因为模型乱答而消失**
3. **她自己先开口时，候选和那句话一起给出来**：提示词末尾让她说完之后另起一行写
   `%% [候选…]`，宿主切开 —— 前半句进气泡，候选直接交给快速回答模块，**省掉原来那次"再问一次
   模型编候选"的请求**

   用 `%%` 而不用 JSON 是刻意的：她的话里随时可能出现引号（中文引号、书名号、"啊？"），一出现
   就把 JSON 弄坏 —— 而"她的话"是最不该被格式绑住的东西。`%%` 之前那半句照旧边生成边冒字；
   模型没照格式写 → 候选为空 → 自动退回第 1、2 层

坑（都是"看起来坏了、其实是一行代码"那种）：

| 坑 | 说明 |
| --- | --- |
| 后台那条连接被记忆占着 | 记忆抽取 + 摘要每轮能占十几秒，挤在一条连接上就永远轮不到 —— 候选单开一个客户端 |
| **客户端没人 tick** | 拆模块时漏了 `tick()` —— 请求发出去没人收结果，表现成"AI 那组从来不出现"。**客户端的状态机得由持有它的模块每帧推** |
| 模型偶尔只吐思考、正文是空的 | 预算被思考吃光。给足 2000，并且**空返回时同一轮再试一次** |
| 气泡 1.8 秒就淡出 | 按钮会跟着消失，而模型那组要几秒才回来 —— 显示按钮时把气泡**按住** |
| `Dictionary` 是引用类型 | `var want := _quick_want` 之后再 `.clear()` 会把 `want` 自己也清空 —— 必须 `duplicate()` |
| 异步回来的东西要认领 | 模型那条几秒后才回来，这期间她可能又说了别的 —— 用"第几代"认领，过期就丢掉 |

**按钮得能点到**：桌宠平时只把"角色轮廓"设为可点区域，其余一律穿透到后面的窗口，所以按钮显示时
会把按钮的矩形**并进可点区域** —— 不做这一步，按钮飘在轮廓外，点上去直接穿过去。

**生闷气**：她主动说完话后 **90 秒**没人理 → 委屈度 +1，并说一句出来。

- 委屈**不靠硬编台词**，而是写进人设的【现在】，所以接下来几轮她的口气会自然带出来，也不会
  每句都翻这件事
- **被理了就消气**：聊天、摸头都算
- 连续被冷落（委屈度 ≥ 2）才**选择性**记进记忆，而且半小时内不重复记 —— 走的是和偷看屏幕
  **同一条观察通道**（四道筛子照过）

## 摸哪儿反应不一样

点她身上不同地方，反应不同 —— 部位在 `pet_pointer.gd` 的 `classify_touch()` 里判：把**按下时**
鼠标的位置换算成"在角色外接矩形里的比例"，再按分带归类。

| 部位 | 分带（归一化坐标） | 反应 |
| --- | --- | --- |
| 头 | 上 26% | 亲昵 + **消气** |
| 手 | 两侧（离中线 26% 以外）且在上 2/3 | 害羞 / 牵手那种 + 消气 |
| 胸 | 中间 26%~52% | **明确不乐意**：凶他、**不消气**，委屈度 +0.5 |
| 腿 | 下 28% | 怕痒 / 躲 + 消气 |
| 身体 | 其余（腰腹那一段） | 随口应一句 + 消气 |

几个刻意的设计：

- **摸到胸必须明确不乐意**。一个 18 岁的女孩子不会笑嘻嘻地接受 —— 写软了这个人物立刻就假了。
  而且 **20 秒内第二次就"屡教不改"**：话变硬、委屈度 +1，还会记一笔"主人手欠"，以后她自己会
  防着点
- 摸到不该摸的**不消气**，反而加委屈度；这条情绪线和"被冷落"是**同一条**，写进人设的【现在】
- 为什么用"**按下时**"的位置：松手那一刻鼠标已经挪开了；而且拖拽结束和"点一下"共用这个回调
- 判部位靠**分带**而不是网格：这个模型是 722 个节点的刚体层级（没有 skin），按网格判非常费劲；
  分带还更好调，想改手感就改那几个数字
- 菜单里的「摸摸头」没有坐标，所以默认按 **head** 算 —— 菜单项本来就叫摸头

### 摸太频繁：她会主动开口，并把这事记下来

一分钟内摸到 8 下（**摸胸算两下**），她就不只是冒一句话了 —— 而是**主动开口让你停手**，并把
这事写进长期记忆。

为什么要走"她自己开口"那条路而不是直接冒一句：那样只是在气泡里闪一句、看完就没了。走这条路
她还会**真的开一次口**，顺带得到：一组专门的快速回答按钮（**不能给她"摸摸头，等会儿陪你"**
—— 那是又摸她一下）、计入"主人多久不理我"、进长期记忆、委屈度 +1。

记忆那一笔**用本地规则先落下**，不依赖 AI、也不花一次请求。半小时内不重复记，否则一晚上能存
十条同义句。**这条回复不再走观察通道** —— 那会变成同一件事存两条。

## 长时间不理她：先偷看一眼屏幕，然后她自己看着办

被冷落 90 秒后的**第一次**，她不是直接闹，而是**偷看一眼屏幕**。但**看到之后怎么理解、要不要
闹、闹到什么程度，全交给她自己** —— 提示词只交代"你在偷看"和她的处境，不给任何判断规则：

```
（主人好久没理你了。你自己偷看了一眼屏幕，看看他到底在忙什么。看到什么就照实说一句，
然后按你自己的想法决定要不要闹、闹到什么程度 —— 想懂事一点也行，想小小地闹一下也行，
一两句话，别长篇大论）
```

她会自己在"懂事"和"闹"之间找个位置，两头都沾一点 —— 这正是不该由我们硬编的地方。

> **否定过一版做法**：让她开头输出 `[忙]` / `[闲]` 标记，本地按标记把委屈度压到 0.5 或抬到
> 1.5。两个毛病：她看到的是**自由文本**（在赶活儿 / 在打游戏 / 在写代码），本来就落在忙碌的
> 中间地带，硬压成两个值必然丢信息；而且判断的后果是我们硬写的，可能和她自己说的话对不上
> —— 嘴上"你去忙吧"，下一句还在闹别扭，读起来就是两个人格。别再走回去。

代价说清楚：**"他在忙 → 委屈度自动降"这个行为没有了** —— 委屈度按"被冷落了几轮"继续累着
（你哪次真回她，一次性清零），她当时怎么判断的则**进长期记忆**。也就是说这件事由她记着、
下次聊起来自然带出来，而不是我们替她记一个数。

第一次之后要是还不理她，就不会再看第二眼，直接继续闹 —— 看一次是"在意"，一直看就成盯梢了。

> 偷看看到的东西本身有信息量（你当时在忙什么），所以这条**比单纯闹脾气更容易进记忆**：
> 闹脾气要连着被冷落两次才记，偷看这条只要过了半小时的间隔就记。
