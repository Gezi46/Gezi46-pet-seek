> 和 Windows 打交道的那一层：托盘图标、全屏检测、开机自启、隐藏任务栏、窗口样式、
> 以及调用本机 dsh 干活。
>
> 返回 [项目主 README](../../README.md)

## 托盘图标

Godot **没有**系统托盘 API，所以图标由辅助进程托管（和全屏检测**共用同一个进程**）：

```
左键点图标 / 菜单「显示 / 隐藏」   收起或叫回她
菜单「退出」                       整个退掉（顺手把辅助进程收掉）
```

托盘和 Godot 之间靠小文件传命令（`user://pet_shell_cmd.txt`），**方向是反的**：状态文件是
我们传给它的"结果"，命令文件是它传给我们的"动作"，读完立刻删。

三个坑：

- **`Window.hide()` 对主窗口无效** —— 直接报 `Can't change visibility of main window`。
  改用 `window_set_mode(MINIMIZED)`：她本来就不在任务栏里，最小化就等于消失。
- **最小化 / 还原会把"不进任务栏"那一位冲掉** —— Windows 会重做一遍窗口样式。所以还原之后
  必须重新设一次。
- **残留的命令文件会误伤下次启动** —— 上次被强杀、或托盘点了退出没来得及删，命令就留在
  文件里，新一次启动会把它当成本次命令执行（一条残留的 `quit` 会让新进程**刚起来就自己退，
  而且什么都不打印**，极难查）。现在启动时先清掉它。

图标就是 `icon.png`（和窗口图标同一张）：导出版里 `res://` 不是真实路径，所以运行时先把它
读出来写到 `user://` 再交给辅助进程。**脚本里那三个菜单文字是中文但以 base64 存在** ——
`.ps1` 必须保持纯 ASCII（PowerShell 5.1 把无 BOM 的 `.ps1` 当 ANSI 读，字符串里的中文会
直接变成语法错误、整个脚本一启动就死）。

> 验证：`tools/probe_tray.gd`。图标"长什么样"没法从代码里断言，那部分得自己看一眼。

## 全屏时安静下来 + 更少的移动

| 参数 | 默认 | 作用 |
| --- | --- | --- |
| `move_chance` | 0.35 | 待机时间到了之后**真的起身**的概率；没中就接着等一轮 |
| `idle_before_move` | (5, 13) | 待机多久才**考虑**动一次（秒，乘 `behavior_pace`） |
| `quiet_when_fullscreen` | 开 | 检测到全屏就进"安静模式"；**关掉则不再留那个后台检测进程** |
| `quiet_radius` | 110 | 安静模式下允许离她当时位置多远（像素） |
| `quiet_idle_scale` | 2.5 | 安静模式下待机时间的倍率 |
| `quiet_move_scale` | 0.5 | 安静模式下单次移动时长的倍率；安静模式**不跑** |

顺序是先掷"做不做表情"（`emote_chance`，原地做手势、不算移动），再掷 `move_chance`。

### 安静模式的活动中心是"她当时的位置"，不是"家"

`home_anchor` 是家，但**不能**拿它当安静模式的活动中心：你一开全屏，她会被瞬间夹到家的
位置，看着就是**瞬移**。所以进入安静模式那一刻把当前窗口位置记成中心（`_quiet_center`）。

活动范围还要和屏幕可用区域求交：家贴着屏幕右边时，光有半径会算出一个屏幕外的框。

### 全屏检测：一个常驻的 PowerShell 小进程

Godot 没有"现在有全屏窗口吗"这种 API，只能问系统。做法是在 `pet_shell.gd` 里内嵌一段
PowerShell、运行时写到 `user://`，用 `OS.create_process` 常驻跑一个 800ms 的循环，把结果
（`1` / `0`）写进 `user://pet_shell_state.txt`，Godot 这边读那个文件。

**为什么常驻而不是"隔几秒查一次"**：每次拉起 PowerShell 都有几百毫秒启动开销，几秒一次
等于一直在烧 CPU；常驻一个进程反而几乎为 0（循环体全是 P/Invoke，没有 cmdlet）。它每 ~10 秒
写一次心跳，所以 Godot 那边**文件超过 15 秒没更新就当作"检测死了"**，不会把过期的"全屏中"
当真（否则宠物会一直缩在小范围里不出来）。死了会自动重拉（冷却 20 秒、最多 3 次）。

### 判据是"所有顶层窗口"，不是"前台窗口"

只看 `GetForegroundWindow()` 是**间歇性的**：一个窗口能不能真拿到前台由系统决定（后台进程调
`SetForegroundWindow` 经常被拒），所以真有全屏视频时也可能漏判。现在扫所有顶层窗口，顺便也
覆盖了"另一个显示器上全屏着"的情况。

两个必须有的过滤：

| 过滤 | 为什么 |
| --- | --- |
| DWM cloaked | UWP／壳窗口的 `IsWindowVisible` 是 true，但其实是被遮蔽的 |
| `WS_EX_TOOLWINDOW` | 工具／离屏辅助窗口不是用户意义上的全屏应用（IDE 的 `CEF-OSC-WIDGET`、桌面的 `Progman` 都是） |

少了这两条，答案几乎是**永久为"全屏中"**。

### 保持置顶：只在真被盖住时才抬

别的置顶窗口（视频小窗、通知）会插到她前面。原来是无条件地周期性调 `SetWindowPos`，结果
她**一闪一闪** —— 窗口是逐像素透明的，每次多余的窗口重排都看得见。

现在只在**真的被盖住**时才抬：沿 z 序往上找，有真实窗口挡在前面才动。"真实"要过滤掉 Windows
自己那堆永远在最上面的东西（判据：类名不在系统名单里、**带 `WS_EX_TOOLWINDOW` 的不算**、
**没有标题的不算**）。

做法是**先关再开**：Godot 的 `window_set_flag` 在值没变时**直接 return**，连着设两次 true
根本不会去调 `SetWindowPos`。而且只在"当前本来就置顶"时才重申 —— 你要是从菜单里关掉了
窗口置顶，这里再强行打开就是跟你对着干。

> 另一个必须知道的 API 事实：`HWND_TOPMOST` 对**已经是置顶**的窗口**不会**改变它在置顶组内
> 的次序 —— 想把一个已经置顶的窗口抬到最前，要用 `HWND_TOP`。

**盖不住的只有一种：独占全屏**（真去改显示器模式的那种全屏游戏）—— 那是 GPU 层面的模式
切换，任何用户态程序都盖不住。无边框全屏（现在绝大多数游戏和视频网站的全屏）能盖住。

## 开机自启动 & 隐藏任务栏图标

| 菜单项 | 默认 | 干什么 |
| --- | --- | --- |
| 开机自启动 | 关 | 登录 Windows 后自动启动（点了才写注册表，不替你做主） |
| 隐藏任务栏图标 | 开 | 不在任务栏和 Alt+Tab 里出现；桌面上照常显示、照常能点 |
| `自启动：已开启` | — | 纯显示的一行，读的是**注册表真实状态**，不是我们自己的开关 |

两个选择都存在 `user://pet_shell.cfg`；缺键时落回**检查器里的导出参数**（不然新加的开关在
老存档上会被读成 false）。

### 开机自启动：写 HKCU 的 Run 项，不碰 HKLM

用**用户级**注册表（不需要管理员权限，也不会影响别人）：`HKCU\Software\Microsoft\Windows\
CurrentVersion\Run`，值名 `DesktopPet`。

菜单那行状态是**去注册表读**的（只认 `reg query` 的返回码）—— 用户可能在"启动项管理"之类的
工具里把它关掉，那菜单就不该还打着勾。

两个坑：

- **写值不能走 `reg add`** —— 要写的那条命令里既有空格又有内嵌双引号，Godot 拼命令行时没法
  转义内层引号，`--path` 被拆成独立参数，reg.exe 直接报"无效语法"。现在改成叫 PowerShell 的
  `Set-ItemProperty`，而且**名字和值都走 base64** —— 只剩 ASCII，中间过几层都不变形。
- **读回来也走 base64** —— 直接回文本时中文路径读回来是乱码（UTF-8 字节被按 GBK 解）。
  注册表里存的其实一直是对的，但那种假乱码会把以后排查的人带沟里。

**值名必须是纯 ASCII**：原来那个中文值名重启后**根本没被执行**，Windows 的启动项记录里也
从来没给它建过条目。所以别再改回中文名。

### 隐藏任务栏图标：Godot 那个 flag 在 Windows 上是空操作

| 做法 | 结果 |
| --- | --- |
| `WINDOW_FLAG_POPUP_WM_HINT` | 窗口 ex-style **一位都没变**，始终带 `WS_EX_APPWINDOW` |
| `WINDOW_FLAG_POPUP` | 主窗口设它直接报 `Main window can't be popup` |
| 自己改 `WS_EX_TOOLWINDOW` | ✅ 有效 |

所以真活儿是叫 PowerShell 去设那一位（`WS_EX_TOOLWINDOW` 置上、`WS_EX_APPWINDOW` 清掉）。

**必须非阻塞调用**（`OS.create_process` 而不是 `OS.execute`）：改窗口样式会给我们**自己的
窗口**发消息，主线程要是正卡在"等 PowerShell 返回"就成了互相等 —— 实测这么卡死过一次。

脚本**内嵌在 `pet_shell.gd` 里**、运行时写到 `user://`，不是放 `tools/`：PowerShell 要的是
一个**真实文件路径**，而导出版里 `res://` 下不是资源的文件压根不进包。

启动那次调用会让窗口闪一下（改完样式要让 shell 重新评估任务栏按钮，得 hide/show 一次），
大概 1 秒后生效。

### 设一次不够：这一位会被反复冲掉

**Godot 自己一动窗口（改尺寸、从最小化还原……）就会重算一遍窗口样式**，把这一位抹掉。
所以现在是让辅助进程**每 800ms 检查一遍并补上**，不是"挑个好时机设一次"。

同一个原因还有个更隐蔽的问题：原来"每 2 秒重申置顶"走的是 Godot 的 flag 机制，**每重申一次
就顺带把任务栏那一位冲掉一次** —— 表现就是任务栏图标忽隐忽现。现在置顶也交给辅助进程用原生
`SetWindowPos` 做（带 `SWP_NOACTIVATE`，不抢键盘焦点），两边不打架。

> 启动那 **~1.5 秒**仍然会有任务栏按钮：PowerShell 起来 + 编译 P/Invoke 要这么久。

### 右键菜单被自己盖住

菜单（PopupMenu）是独立系统窗口（`embed_subwindows=false`），它和宠物**都是置顶窗口**，
谁在上面取决于谁最后被抬起 —— 而宠物一移动（`window_set_position`）就会被 Windows 抬到
置顶组最前面，于是菜单一打开就被她盖住。

**改法**：菜单开着时把宠物**从置顶里摘出去**（连 Godot 那边的标志一起摘，否则 Godot 会在她
下次动窗口时又加回来）。这样"菜单（置顶）在宠物（非置顶）之上"是 Windows 的硬保证，跟先后
顺序无关；菜单一关就恢复。

> 验证：`tools/probe_shell.gd` —— 它**问 Windows 本身**要窗口 ex-style（而不是问 Godot），
> 再走一遍自启动的写→读→删。要带窗口跑，不能用 `--headless`。

### 自启动没生效时，按这个顺序查

0. **先看 `%APPDATA%\Godot\app_userdata\桌宠\pet_start.log`**（每次启动追加一行：时间 /
   可执行文件 / 命令行 / 自启动登记状态）。**没有这一次的时间 = 进程压根没被拉起来**，
   问题在系统那边，不在桌宠里。
   > 这行**不能**指望引擎日志：导出版里 `print()` 不进 `logs\godot.log`，而自启动跑的正是
   > 导出版 —— 所以这行证据是自己写进 `pet_start.log` 的。
1. **确认是不是"真重启"**：`HiberbootEnabled = 1`（快速启动，Win10/11 默认）时，"关机再开机"
   是**从休眠恢复**，容易漏掉真正的登录流程 —— 测试请用开始菜单里的**「重启」**。同理，
   **休眠/睡眠**不会触发自启动。
2. **看 Windows 有没有把它禁用**：设置 → 应用 → 启动。被禁用之后 Run 项还在，但不会执行，
   状态记在 `HKCU\…\Explorer\StartupApproved\Run`。
3. **手动跑一遍登记的那条命令**（`reg query "HKCU\…\Run" /v DesktopPet` 拿到值，粘进"运行"）。
   能起来 → 登记没问题，回去看第 0/1/2 条。

### 这条命令为什么写得这么"笨"

登记的值就是**一条最普通的 exe 启动命令**，路径用**反斜杠**、整条加引号。**不要**在这里加
脚本、base64、隐藏窗口之类的东西 —— 两个坑都是撞出来的：

- **`.cmd` 里拼中文路径会散架**：cmd.exe 按 OEM 代码页读 `.cmd`，`…\桌宠` 落盘再读出来成了
  乱码，那条路径根本打不开。
- **`powershell -EncodedCommand` 那套被杀软直接删了**：隐藏窗口 + 编码命令 + 拉起进程，正是
  恶意软件的典型特征 —— 报毒是应该的，自启动里不该出现这种东西。

**登记的是哪条命令**：导出版里点开关 → 登记 exe 自己的路径（自包含）；在编辑器里点 → 登记
`"<godot.exe>" --path "<项目目录>"`（没导出也能先验证）。所以**开发时想让她跑最新代码，就在
编辑器里开关一次；想要稳，就用导出的 exe 开关一次**。

## 让她调用本机 DeepSeek Harness 干活

右键 →「聊天与 AI」→「让她用 dsh 干活」，然后在聊天框里说：

```
干活：用一句话说明为什么天空是蓝色的
```

她先按住气泡说一句，跑完把结论**用自己的口气**讲回来；dsh 的原文另外留一份在聊天记录里。
派活的说法认好几种：`干活：` `干活:` `dsh：` `dsh:` `/dsh ` `让dsh `。

### dsh 是什么、为什么这么调

`@deepseek-ai/dsh` 是装在本机 npm 缓存里的 agent harness，平时双击启动器会用 `node bin.js
web` 起个 Web UI。我们用的不是那个界面，而是它的**一次性任务模式**：

```sh
dsh --profile headless "任务文本"     # 跑一个全新会话，答案打到 stdout，退出
```

官方原话是"不开端口、不留后台，适合脚本与一次性任务"，退出码 0 = 完成。

不去 HTTP 调它那个 Web 服务，三个理由：一次性模式本来就是给脚本用的（stdout 即答案、退出码
即成败，比猜它家前端接口稳得多）；不管端口在不在跑都能用；不用管它的登录态和会话列表。

### 推理档按工作量自动配

dsh 的 deepseek 适配器只认四档 `off / low / high / max`（`off` = 不开思考），而 headless
**没有对应命令行参数** —— 这一项属于"设置层"，真源是 `~/.dsh/settings.yaml` 里的
`agent-default-model.reasoningEffort`。所以流程是：

```
估一档 → 临时改设置文件 → 跑 → 原样改回去
```

估分（`effort_score()`）是几个维度相加，权重写死成常量，好照着自己调：

| 维度 | 权重 |
| --- | --- |
| 长度 | 40 字 1 分，最多 2.5（再长不代表更难） |
| 拆成几件事（换行 / "然后""另外"） | 每个 +0.7，最多 2.1 |
| 重活关键词（分析 / 设计 / 为什么 / 代码…） | 每个 +1.2，最多 4.8 |
| 轻活关键词（"一句话""翻译""查一下"…） | 每个 -0.8，最多 -2.4 |

分数 → `off`（<1）/ `low`（<2.5）/ `high`（<5）/ `max`。另外两条兜底：

- **带了重活关键词的至少给 `low`** —— 否则"用一句话说明为什么天空是蓝色的"会被"一句话"扣成
  `off`，可它问的是"为什么"，不想一下就答只能背课文
- 设置里的「最高推理档」是**天花板**：想让额度有上限就压低它，任务再大也不会超过

### 两个不得不绕的坑

**1）中文乱码 → 多一个 node 转发器**

直接用 `OS.execute` 收 dsh 的 stdout，中文回来是乱码 —— Godot 在 Windows 上按系统 ANSI 代码页
解码子进程输出，而 node 写的是 UTF-8，有些字节直接变成 `?`、**不可逆**。
（任务**传过去**是好的：拼命令行走 CreateProcessW，中文没问题。）

所以让 node 帮个忙：运行时写一个十几行的转发器到 `user://pet_harness_runner.js`，它用**文件
描述符**把 dsh 的 stdout / stderr 接到两个文件上（原始字节，一个字节都不动）。顺带白拿
stderr = 它那串推理流。

**2）不能卡住她 → 工作线程**

`OS.execute` 要等子进程结束（一次五秒起），在主线程里调就是把桌宠卡住。所以丢给一个工作线程，
主脚本每帧 `poll()`。线程里只写几个字段（bool / String / int），不碰场景树、不发信号。

### 会动别人的文件，所以特别小心

`~/.dsh/settings.yaml` 是你的文件，我们只做一件事：把那一行的值换掉，跑完**把读到的整份内容
原样写回**（不引 YAML 库、不重排任何一行 —— "顺手整理一下配置文件"正是这类功能最典型的
翻车方式）。改档是纯字符串函数（`with_effort()`）：

- 键在 → 换值（保留它自己的缩进），**不增删任何行**
- 键不在但段在 → 补在段里（缩进照抄同段），不能掉到文件末尾变成顶级键
- 连段都没有 → 末尾整段补上

读不到设置文件就不改它（宁可这一趟用你原来的档）；退出时也会还原。

### 开关与其它

- **默认关**：它会在你机器上真跑一个 node 进程、花你的额度，这种事得你主动开
- 开关在两处：右键 →「聊天与 AI」→「让她用 dsh 干活」，以及设置面板的「AI 服务」那一组
- 跑活期间她会按住气泡，`_ai_busy()` 也算上它 —— 这时候跟她说话，她会说"我还在弄那件活呢"
- 退出时不掐正在跑的活（dsh 是一次性进程，跑完自己退），但设置文件一定还原
- 找不到 dsh 时她会直说找不到（而不是没反应）；`bin.js` 是**扫**出来的，不写死 npx 那个哈希
  目录（官方启动器写死了，换版本就失效）

## 整合启动：一个 bat 把 AI 服务和桌宠一起拉起来

`启动桌宠.bat` 做两件事：**先确认本地 AI 服务在跑**（不在就拉起来，最多等 24 秒），**再启动
桌宠**。服务没起来也不影响桌宠运行，只是聊天退回本地台词。

### 写 bat 的三个坑

早期版本**根本启动不了桌宠**，症状还很难懂：cmd 报 `'t-Null' 不是内部或外部命令` —— 一行命令
被拆成碎片逐个执行。三个原因叠在一起：

| 坑 | 表现 | 正确做法 |
| --- | --- | --- |
| bat 行里的 `\|` | cmd 当管道符，PowerShell 一行命令被劈成两半 | 一行里别用 `\|`，改用 `> $null` 重定向 |
| UTF-8 + 中文 + LF 换行 | cmd 按当前代码页逐行解析，多字节字符和 LF 会让解析错位 | bat 保持**纯 ASCII + CRLF** |
| `--path "%~dp0"` | `%~dp0` 结尾是反斜杠，`\"` 被当成转义引号，整条命令行拆坏 | 结尾补一个点：`"%~dp0."` |

最后一条最隐蔽：**原版就是这个写法，也就是说它一直是坏的**，只是平时多半从编辑器 F5 启动
才没暴露。两个 bat 都已按上表改好（非 ASCII 字节 = 0、全 CRLF）。
