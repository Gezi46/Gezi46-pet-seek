>
> 返回 [项目主 README](../../README.md)
## 动画节奏（整体放慢）

`desktop_pet.gd` 顶部的 **动画节奏** 分组里有三个倍率，都能在检查器里实时调：

| 参数 | 默认 | 作用 |
| --- | --- | --- |
| `anim_speed` | **0.7** | 所有动画的播放速度倍率（主体和眨眼叠加层一起生效） |
| `blink_slowdown` | **2.5** | 眨眼间隔倍率，越大越少眨眼 |
| `behavior_pace` | **1.3** | 待机 / 散步的时段整体拉长，越大越"懒" |

`anim_speed` 走的是 `AnimationPlayer.speed_scale`，所以顺带做了两件配套的事：

- **走路的位移速度同步缩小**。`_begin_move()` 里 `_speed` 乘了同一个倍率 ——
  不然步频慢下来了、窗口还按原速平移，脚底会明显打滑。
- **动作后的等待时间按 `_beat()` 换算**。原来写死的 `_timer = 0.6` 全部换成
  `_timer = _beat(0.6)`（即 `0.6 / anim_speed`）：动作本身变慢了，等待时间也得
  同比拉长，否则动作还没播完就被打断回待机。
- **眨眼概率除以 `blink_slowdown`**，而不是去改 `blink_chance` 的初值。

想让动作回到原始速度：`anim_speed = 1.0`、`behavior_pace = 1.0`、`blink_slowdown = 1.0`。

## 移动方向与朝向

人物会朝**移动方向**转身，而不是永远正对屏幕：

| 屏幕上往哪走 | 3D 里看到的 |
| --- | --- |
| 向右 | 偏航 -90°，看到侧面 |
| 向左 | 偏航 +90°，另一侧侧面 |
| 向上 | 偏航 0°，**背对镜头**往远处走 |
| 向下 | 偏航 180°，正对镜头走近 |

坐标对照（相机在 +Z 看向原点）：屏幕右 = 世界 +X、屏幕上 = 世界 -Z。
换算就是 `yaw = atan2(-dir.x, -dir.y)`，见 `_facing_target_yaw()`。
**静止时会转回 `FACING_BASE`（正对屏幕）**，所以停下来的样子和以前一致。

| 参数 | 默认 | 作用 |
| --- | --- | --- |
| `face_move_direction` | **1.0** | 1 = 完全朝移动方向；0 = 永远正对屏幕（旧行为）；中间值可折中 |
| `allow_vertical_move` | **true** | 会不会往屏幕上下方向走 |
| `vertical_move_weight` | **0.7** | 上下相对左右的出现权重（1 = 同概率） |

### 家（初始位置）与回家引力

桌宠有一个"家"：**启动时就停在那儿**，飘得离它越远，下一次走路越可能朝家的方向走。

| 参数 | 默认 | 作用 |
| --- | --- | --- |
| `home_anchor` | **(1.0, 1.0)** | 家的位置，屏幕可用区域的归一化坐标（0~1）：(1,1) = 右下角、(0.5,1) = 底部居中、(0,0) = 左上角 |
| `home_deadzone` | **150** | 离家这么远以内算"在家附近"，不施加任何牵引（像素） |
| `home_pull` | **0.8** | 牵引强度：0 = 关闭（永远随机走）；1 = 远到屏幕半对角线时必然往回走 |
| `drag_sets_home` | **true** | 拖拽放下后把落点当成新的家；关掉则拖拽只是临时挪一下 |

**三种改家的方式**：

1. 检查器里直接改 `home_anchor`（分组「窗口」）；
2. 右键菜单 →「把当前位置设为家」—— 先拖到想放的地方，再用菜单记下来；
3. 直接**拖拽**放下（`drag_sets_home` 打开时）—— 拖到哪儿哪儿就是家。

### 只在小范围走动（不想让她满屏溜达时）

右键 →「位置与窗口」→「只在小范围走动」，或设置面板「窗口与操作」里同一个开关。
开了之后她只在家附近 `nearby_radius`（默认 220px）的方块里转。

两个刻意的设计：

- **已经在圈外不瞬移**：一开开关就把她拽回家，比不管还吓人（安静模式那条注释里
  已经踩过这个坑）。所以规则是"先不夹，等她被回家引力拉着溜达回来再开始管" ——
  看起来就是"她回来了"，而不是被吸过去
- 和**安静模式共用一套机制**（都在 `pet_walk._step_move` 里对活动范围求交），区别只在中心：
  安静模式是"进入全屏那一刻她所在的位置"（自动触发的，更不能瞬移），
  这个就是**家**（你主动开的开关，本来就希望她待在窝附近）。两个同时开着就是取交集

还想更省心的话，同一组里另有「起身走一次的概率」（`move_chance`，默认 0.35）——
调小 = 她起身的次数变少，调到 0 就完全不动了（摸头 / 眨眼 / 呼吸照常）。

> 验：`tools/probe_memory.gd` 的离线段试 `nearby_box()`（中心 / 边长 / 半径填 0 不塌）；
> 真机那次是让她走 400 步，看"有没有一帧跑出圈""在圈外会不会被瞬移""关掉后能不能走远"。

后两种都会写进 `user://pet_home.cfg`（Windows 下是
`%APPDATA%\Godot\app_userdata\桌宠\pet_home.cfg`），下次启动仍停在那儿。
不写回 `scenes/pet.tscn` 是有意的：拖一下就把场景文件改掉太意外，也不好回滚。
想回到出厂设置：右键菜单 →「初始位置恢复右下角」（等价于 `home_anchor = (1,1)`）。

停靠位置算的是**窗口能落到的范围**（可用区域减去窗口自身）再乘锚点，
所以 (1,1) 是右下角贴边、(0.5,1) 是底部居中 —— 窗口大小和任务栏高度都不影响，
停下去不会露出一截在屏幕外。回家引力也是量到"家的窗口位置"的像素距离。

牵引概率从死区处的 0 线性爬到半对角线处的 `home_pull`，所以只是偶尔飘远，
不会刚出门就被拽回去；方向按离家向量的两轴分量加权挑，斜着离家就斜着回去。
实现见 `_home_pos()` / `_home_pull_dir()` / `set_home_here()`，
验证见 `tools/probe_home_pull.gd`（**要带窗口跑**，headless 下 `window_get_size()` 是 0，
停靠位置和"离家多远"都测不出来）。

> 旧实现是"走动时只从正面偏转 ±20°"，所以看着总是大致正对镜头；
> 现在换成真正的转向，`FACING_SWING` 那个常量已删除。


## 性能上做的两件事

`_process()` 里唯一的每帧大头是角色包围盒：悬停检测和"可点区域"每帧各要算一次，
而每次都要遍历 **567 个 `MeshInstance3D`**。改了两处：

| 改动 | 效果 |
| --- | --- |
| 包围盒按 `AABB_REFRESH_FRAMES`（默认 3）帧节流，且一帧内复用 | 每帧遍历次数 2 次 → 约 0.33 次 |
| `_compute_model_aabb()` 改用 `Transform3D * AABB`（C++ 里算），不再自己循环 8 个端点 | `_calibrate()` 启动要按帧采样几百次，那 567×8 次 GDScript 向量变换是启动卡顿主因；改完校准结果逐位一致（`S` 只差 1e-6） |

顺手修了一个**帧率相关的 bug**：窗口位置只能取整像素，原来写的是
`int(_facing * _speed * delta)` —— 60fps 下 46px/s 算出来是 0.77，`int()` 直接截成 0，
**走得动走不动完全看帧率**。现在用 `_move_accum` 把不足 1px 的位移累积起来再取整。
`_update_facing()` 里也把 `rotation.y` 归一到 `[-PI, PI]`，避免连续转向时数值一直累加
（跑一整天后 float32 精度会变差）。
